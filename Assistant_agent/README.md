# 极简 DeepSeek 万能助手

## 启动方法

运行环境要求 Python 3.10 或更高版本，不需要 `pip install`。

1. 打开项目根目录的 `config.json`。
2. 将 `api_key` 从空字符串改成自己的 DeepSeek API Key。
3. 在项目目录打开 PowerShell，启动交互助手：

```powershell
cd "E:\极简架构agent"
python -m agent_lab
```

看到 `你 >` 后直接输入自然语言。输入 `/help` 查看交互命令，输入 `/quit` 退出。

也可以设置 `DEEPSEEK_API_KEY` 环境变量覆盖配置文件中的值。默认模型是 `deepseek-chat`，接口地址是 `https://api.deepseek.com`。

如果 API Key 仍为空，交互界面依然可以启动；填写配置后输入 `/reload`，不需要退出程序。单轮调用可以执行：

```powershell
python -m agent_lab ask "解释一下什么是 Agent 架构"
```

## 架构思想

这是一个**不使用任何 Agent 框架**的交互式 DeepSeek 助手。项目只依赖 Python 标准库，把五种 Agent 架构封装成可独立运行、也可由统一助手自动调用的能力。

这里的“封装”不是引入 LangChain、LangGraph、AutoGen、CrewAI 等第三方框架，而是让每种架构具有清晰的输入、输出、状态和权限边界，可以单独阅读、测试和替换。

### 两层架构

“万能助手”不是把所有能力塞进一个超大提示词，而是由两个清晰层次组成：

```text
用户输入
  ↓
会话记忆
  ↓
自动路由：判断当前请求适合哪种工作方式
  ↓
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│ 通用对话 │ 本地问答 │ 工单处理 │ 规划执行 │ 多角色评审 │ 内容审批 │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
  ↓
结构化结果
  ↓
写入会话记忆并返回用户
```

- **外层组合架构**负责会话记忆、意图路由、模式切换和结果汇总。
- **内层 Agent 架构**负责真正完成任务，每种模式只解决一类问题。
- **共享内核**负责模型调用、JSON 解析、工具注册、执行轨迹和配置。

路由器只输出结构化意图，Python 会校验意图是否在允许列表中。路由模型不可用时，会退化为关键词判断；无效意图不会直接控制程序流程。

### 模型负责认知，代码负责边界

这是本项目最重要的设计原则。

| 责任 | 模型 | Python |
| --- | --- | --- |
| 理解自然语言 | 主要承担 | 提供必要上下文 |
| 提取和生成内容 | 主要承担 | 校验结构与字段 |
| 决定使用哪种架构 | 给出意图建议 | 白名单校验和分发 |
| 控制循环次数 | 不控制 | 设置最大步数 |
| 工具权限 | 只能选择已注册工具 | 决定工具是否可见及路径边界 |
| 状态是否合法 | 不控制 | 显式状态机负责校验 |
| 是否允许人工扩展流程 | 不控制 | 代码决定重试、终止和审批 |

模型擅长理解与生成，但不应成为权限、循环、状态和安全边界的最终控制者。把确定性规则留在普通代码中，可以降低不可预测性，也让核心逻辑能够脱离真实模型进行测试。

### 按任务形态选择架构

五种架构不是用来炫耀“多 Agent”，而是对应五种不同的任务结构：

- **固定工作流**：步骤稳定、规则明确，例如工单分诊。模型只填内容节点，路由和 SLA 由代码决定。
- **ReAct**：下一步取决于上一步观察，例如查询多个本地文件。模型自主选择工具，代码限制工具范围和最大循环次数。
- **规划—执行—验收**：最终交付物较复杂，需要先拆解再检查。计划、执行和验收分离，避免一次生成后无人校验。
- **多角色协作**：同一问题需要不同视角。分析师、批评者和决策者使用隔离上下文，减少角色观点互相污染。
- **状态机**：任务会暂停、恢复或等待人工决定。状态、合法转换和持久化由代码管理。

选择顺序遵循“能简单就不要复杂”：

```text
一次回答足够 → 普通对话
步骤固定 → 固定工作流
下一步依赖观察 → ReAct
需要完整交付物 → 规划执行
需要多视角冲突 → 多角色协作
需要暂停和人工决定 → 状态机
```

### 轻量模式优先

自动路由优先选择成本最低、控制最简单的模式。普通解释、闲聊和一般编程问题直接使用单次模型调用，不会因为系统具备规划或多 Agent 能力就被强行送入复杂流程。

复杂架构只有在任务结构确实需要时才启用。这不仅减少 API 调用次数，也减少错误来源和不可解释的中间状态。

### 显式状态和可恢复性

会话记忆和审批状态都会保存到本机 JSON 文件。状态不是隐藏在模型上下文里的“感觉”，而是程序可以读取、校验和恢复的数据。

状态机只允许合法的转换，例如只有 `pending_review` 才能人工通过或拒绝。即使程序关闭再启动，待审批任务仍然存在。

### 上下文隔离与显式交接

多角色模式不会让三个角色看到无限增长的同一段对话，而是按阶段传递必要信息：

```text
提案 → 分析师 → 分析结果
提案 + 分析结果 → 批评者 → 批评意见
提案 + 分析 + 批评 → 决策者 → 最终结论
```

每个角色接收的是完成自身工作所需的最小上下文。这样可以减少提示污染，也便于检查某个结论基于哪一部分信息。

### 可观测、可测试、可替换

- `Trace` 记录模型决策、工具调用和状态转换，可使用 `/trace on` 查看。
- 所有模型调用都依赖同一个 `ChatModel.complete(...)` 接口，测试时可注入脚本模型。
- 每种架构都有独立函数入口，可以绕过交互层单独运行。
- JSON 输出经过统一解析和字段校验，不合法结果会明确失败，而不是静默继续。

### 安全边界也是架构的一部分

- 本地问答只允许读取指定目录中的 Markdown 文件，不执行任意 Shell 命令。
- ReAct 有最大循环次数，工具异常会作为观察结果返回，不会直接让进程崩溃。
- 内容审批区分模型初审和人工决定，模型不能替代人工通过中风险内容。
- 真实 API Key 只保存在本地配置文件或环境变量中。

这套设计的最终目标不是让模型获得无限自由，而是让它在清楚的边界内完成适合模型的工作，同时让流程、状态、权限和失败处理保持可见、可控、可测试。

## 交互示例

启动后可以直接输入：

```text
你 > 你好，先简单介绍一下你能做什么
你 > 这个项目的验收要求是什么？
你 > 我昨天被重复扣款两次，今天还登录失败，请尽快处理
你 > 帮我设计一个两周内上线内部知识库的完整计划
你 > 评估一下：投入两人一个月自研搜索系统的提案
你 > 审核这段周五促销文案是否合规：全场五折，名额有限
```

助手内部会自动路由，但不会把普通问题强行送进复杂流程。也可以在界面中强制切换模式。

## 交互命令

| 命令 | 用途 |
| --- | --- |
| `/help` | 显示全部交互命令 |
| `/mode auto` | 恢复自动路由 |
| `/mode chat` | 强制普通对话 |
| `/mode notes` | 强制本地资料问答 |
| `/mode support` | 强制工单处理 |
| `/mode plan` | 强制规划执行 |
| `/mode review` | 强制多角色评审 |
| `/mode approval` | 强制内容审批 |
| `/paste` | 输入多行内容，以 `/end` 结束 |
| `/trace on` | 显示子 Agent 的工具和阶段轨迹 |
| `/history` | 查看当前会话记录 |
| `/clear` | 清空会话记忆 |
| `/reload` | 重新读取 `config.json` |
| `/approval status` | 查看当前审批单 |
| `/approval approve [备注]` | 人工通过待审核内容 |
| `/approval reject [备注]` | 人工拒绝待审核内容 |
| `/quit` | 退出 |

会话默认保存在 `data/runtime/assistant_session.json`，最多保留最近 24 条消息。使用 `--no-history` 可以关闭持久化：

```powershell
python -m agent_lab assistant --no-history
```

## 自动路由

| 模式 | 自动选择时机 | 实际调用 |
| --- | --- | --- |
| `chat` | 普通问答、解释、写作、编程、闲聊 | DeepSeek 直接回答 |
| `notes` | 询问项目文件、README、笔记或验收要求 | ReAct + 本地 Markdown 工具 |
| `support` | 客服工单、投诉、退款、登录故障 | 工单分诊固定工作流 |
| `plan` | 复杂方案、报告、计划、长文或开发任务 | 规划—执行—验收—修订 |
| `review` | 评估提案、决策、风险或方案比较 | 分析师—批评者—决策者 |
| `approval` | 合规检查、文案审核、能否发布 | 状态机 + 人工复核 |

路由器只输出结构化意图；具体步骤仍由普通 Python 代码控制，因此可以单独测试和替换。

## 五个 Demo

| Demo | 实际用途 | 架构重点 | 适合场景 |
| --- | --- | --- | --- |
| `workflow` | 客服工单提取、分级、路由和回复 | 模型节点固定在代码流程中，规则由 Python 控制 | 步骤稳定、结果需要可复现的业务流程 |
| `react` | 查询本地 Markdown 资料并回答 | 模型自主选择 `list_notes` / `read_note` 工具 | 路径不固定，需要根据观察逐步探索 |
| `planner-executor` | 把复杂请求拆解、执行、验收和修订 | 计划器与执行器分离，增加验收器闭环 | 报告、方案、长文本等一次性复杂交付 |
| `multi-agent` | 对提案进行正确性分析和风险评审 | 分析师、批评者、决策者使用隔离上下文 | 需要多视角审查且单次提示容易遗漏 |
| `state-machine` | 内容合规初审与人工复核 | 显式状态、合法转换、JSON 持久化 | 长流程、需要暂停、恢复和人工审批 |

## 目录结构

```text
agent_lab/
├── assistant.py               交互入口、自动路由、会话记忆
├── config.py                  配置加载与校验
├── llm.py                     DeepSeek 标准库 HTTP 客户端
├── parsing.py                 容错 JSON 解析
├── tools.py                   工具注册、执行和错误隔离
├── trace.py                   轻量执行轨迹
└── demos/
    ├── workflow.py            固定工作流
    ├── react.py               ReAct 工具循环
    ├── planner_executor.py    规划—执行—验收
    ├── multi_agent.py         多角色协作
    └── state_machine.py       状态机 + 人工审批
```

共享内核只依赖一个抽象接口：

```python
model.complete(messages, temperature=None, json_mode=False) -> str
```

每个 Demo 都可以注入自己的 `ChatModel` 实现，因此测试时不需要真实 API，将来替换模型也不需要修改业务流程。

仍然可以绕过统一助手，单独运行某个 Demo：

```powershell
python -m agent_lab list
python -m agent_lab workflow "我昨天被重复扣款两次，今天还登录失败"
python -m agent_lab react "这个项目的验收要求是什么？"
python -m agent_lab planner-executor "为一个小团队设计一个每周技术分享流程"
python -m agent_lab multi-agent "下个月投入一周时间上线 AI 客服，首月预算 2 万元"
python -m agent_lab state-machine submit "本周五全场五折，名额有限，先到先得"
```

## 常用参数

所有调用模型的 Demo 都支持：

| 参数 | 用途 |
| --- | --- |
| `--config PATH` | 使用另一份配置文件 |
| `--quiet` | 隐藏执行轨迹 |
| `--json` | 输出适合程序继续处理的 JSON |

`react` 还支持 `--notes-dir` 和 `--max-steps`；`planner-executor` 支持 `--max-tasks`；`state-machine` 支持 `--state-file`。

查看具体参数：

```powershell
python -m agent_lab workflow --help
python -m agent_lab state-machine --help
```

## 状态机人工复核

`state-machine` 会把状态保存在 `data/runtime/approval_state.json`。中等风险内容进入 `pending_review` 后，可以执行：

```powershell
python -m agent_lab state-machine approve --note "人工确认内容符合规范"
python -m agent_lab state-machine reject --note "人工复核发现缺少必要资质信息"
python -m agent_lab state-machine reset
```

只有 `pending_review` 状态允许人工通过或拒绝。高风险内容会直接进入 `rejected`，低风险内容会进入 `approved`。

## 测试

测试使用脚本模型，不消耗 API 额度：

```powershell
python -m unittest discover -s tests -v
```

测试覆盖助手自动路由、会话记忆、配置校验、模型 JSON 解析、工单路由、ReAct 工具路径限制、规划流程、多角色决策和状态转换。

## 安全边界

- `config.json` 中默认不包含真实密钥。
- 会话记忆只保存在本机 `data/runtime`，不会上传到额外服务。
- Anthropic 风格的任意命令工具没有加入 Demo；`react` 只允许读取指定目录中的 Markdown 文件。
- `state-machine reset` 会删除当前演示状态文件，只对项目内的 `data/runtime` 生效。
- 模型输出都会做结构校验。如果 DeepSeek 返回不符合协议的 JSON，程序会明确报错，而不是带着错误数据继续执行。
