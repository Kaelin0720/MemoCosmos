# 常见问题

简体中文 · [English](en/troubleshooting.md)

## 启动失败

**找不到后端环境**：在项目的 `backend` 目录执行 `uv sync --locked`，然后回到根目录启动。不要把系统 Python 当成已经安装依赖的项目解释器。

**前端尚未构建或代码比构建结果新**：在 `frontend` 目录执行 `pnpm build`，再启动。日常使用静态构建；修改源码时可以运行 `run.py --dev`。

**端口被占用**：MemoCosmos使用本机 `3000` 和 `8000` 端口。先关闭已经启动的MemoCosmos或其他占用服务，再重试。启动器不会强制停止其他程序。

**找不到 pnpm**：先安装 Node.js 22 或以上，再执行 `npm install -g pnpm@11.19.0`。安装 uv 的方法见 [官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)。

**依赖下载失败**：检查网络连接。Python 依赖使用官方 PyPI；公司网络、代理或证书设置可能影响访问。不要为了避开下载失败删除锁文件或随意升级依赖。

## 页面连接不上本机服务

使用根目录 `run.py` 启动并保持终端或 PyCharm 运行窗口打开。访问 [健康状态](http://127.0.0.1:8000/health) 检查后端是否启动，再在设置页点击检查连接。

静态页面默认通过统一启动器访问同源 API，仅用普通静态文件服务器打开 `frontend/out` 不会提供 API 转发。推荐使用统一启动器，不必分别启动前后端。

## 保存配置后仍无法聊天

保存成功代表本机已经存下配置，不代表云端已连通。检查 API 基址、模型 ID、密钥有效性、账号余额与模型权限。模型还需要支持工具调用和流式输出。

如果出现 404，检查是否把完整的 `chat/completions` 地址填成了 API URL，或遗漏供应商要求的版本路径。不同服务的基址不同，请以供应商文档为准。

如果页面显示配置暂时无法安全保存，检查本机配置目录是否与源码或记忆库重叠，以及当前用户是否有权限。Windows 用户请在 WSL2 Ubuntu 内运行，并把应用与记忆库放在 Linux 用户目录。原生 Windows 尚不支持完整文档存储。

不要在 Issue 或聊天中粘贴 API Key。反馈问题时可以提供错误类型、操作步骤、操作系统和依赖版本，移除个人内容、密钥和私密路径。

## 聊天完成但没有生成笔记

打开 **知识宇宙 → 整理与确认** 查看任务状态。没有新增保存价值时会跳过；有歧义时等待你确认；配置或网络失败则显示失败原因。整理在聊天后后台执行，不会每条消息立即产生新文档。

检查设置里的自动整理开关。需要明确保存时，可以在聊天中告诉助手希望记住哪些内容。

## 检索结果不完整

可以补充标签、主题词或更具体的问题，并查看结果的覆盖提示。当前采用标签、关键词和章节检索，尚未提供向量语义检索或全年度自动汇总。

如果直接修改过磁盘上的 Markdown，请先回到文档核对并导入外部变更，再检索。

## 导入后仍显示旧记忆库

恢复只在新的目录生成资料库，不自动替换当前运行的库。复制返回的目录，关闭当前服务，然后使用 `run.py --memory-dir` 指定它重新启动。详细步骤见 [使用与迁移](usage.md)。

导入失败时检查文件是否为MemoCosmos导出的完整 ZIP，是否损坏、超出大小限制或被手动修改。不要直接解压覆盖正在运行的资料库。

## 关闭之后数据会丢失吗

已确认保存的笔记、对话与分类保存在本机磁盘，重启可以继续使用。未保存草稿只存在于当前页面会话，关闭前需要保存。云端生成途中停止服务会保留已收到的内容，并把未完成任务标记为中断。
